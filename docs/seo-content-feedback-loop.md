## 两种关键词检查分开完成

### 已有排名覆盖

域名排名盘点回答“我们已经在哪些词上获得排名”，不是“预选词池中有多少词命中”。获取Flatkey四个目标市场的域名自然排名观测，保留原始 `keyword × country × URL`，再分层统计：

1. 原始数据库覆盖及各国实际返回量、总量／分页依据和截断；自有品牌、非自有品牌及语言不明项可追溯。
2. 主指标为四国符合已批准国家语言条件的非自有品牌排名词并集。每个规范化关键词只计一次，展示相同证据口径下的最佳有效排名及对应URL；各国词数不能相加冒充并集，同词多个URL也不重复计数。
3. 业务价值、是否正式池、是否绑定Topic、人工页面关联、搜索量和KD用于下一步投入判断，不作为已有排名事实的排除门槛。清理活跃词库不得改写历史排名总数。

本次市场范围为US/en、JP/ja、ES/es-ES、BR/pt-BR。先校验原词与当地语言／业务市场适合性，再比较合格国家；不因全球最佳国家语言不符而删除其他有效观测。接口语言参数不证明原词语种；通用型号、混合语言或无法确认的词保留原观测并待核对，不擅自翻译或认作英语。自有品牌沿已确认的26词排除表；第三方产品／型号词单列，不能暗中扩成“所有第三方实体都删除”。

当前旧Labs流程每国最多1000条且不自动分页，只能称已取得的索引范围，不等于全量。完整覆盖须以获批分页上限、实际逐页回执及供应商可访问总量验收；未取尽如实保留截断，不自动追加收费。供应商数据库发现、GSC有曝光查询和实时SERP是不同证据，不互相替代；数据库更新时间不是本次读取时间。

原`seo-09-30-2`及隔周复盘须消费`GET /api/seo/ranked-keyword-coverage?periodKey=<原周期>`的同周期服务端汇总。该入口只读已完成的四国`dataForSeoRun.normalized`，零供应商请求、零新增费用，不采集、不导入、不续跑，不改变付费开关或原调度；支持原登录会话及已有SEO Bearer只读认证。只接受明确周期，或四个同周期既有`runId`，不自动拼入别期或另建job。

每次将API确切响应、内容SHA-256、原周期／四个runId、实际采集日、供应商索引更新时间及完整性说明留存并关联原复盘回执。分别使用原返回项数、有效观测行数、各国独立词数和四国并集，不把同词多URL或各国词数相加；缺国、未完成、截断及无效观测如实标为不完整，不自动收费补齐。API的`totals.rawNonBrandDistinctKeywords`明确**未按原词语种筛选**，请求locale不证明原词语言；在`scope.originalWordLanguageReviewComplete=false`及严格语种指标为null时，只能报告原始数据库覆盖，不能冒充上文严格语种主指标。最佳观测国家仅作展示，保留全部国家／URL和原子域范围，不等于写入主国分配。

## 同一份内容决策与任务去重

周报和隔周复盘共用同一份决策记录，每项至少写清：主题／原词、实际页面及国家语言、事实与限制、保留／加码／优化／暂停／归档动作、业务价值及优先依据、对应任务、验收指标和下次检查条件。上涨不自动证明新增篇数导致，下跌不自动证明算法处罚；页面、国家和来源切片不能混加，GA4会话与GSC点击不混比。

每个可执行结论在平台有对应taskId；已有任务覆盖时只补证据，不重复新建。纯背景统计不为凑数建立制作任务；需要观察或补证时建立有明确对象和复查条件的研究／review候选。

1. 写前读取全量相关任务、issue、各周计划、已发布／草稿／预留意图及TopicMap。首先按原taskId／keywordId和真实URL匹配，再核对同站、语言、市场、意图和问题类别。
2. 使用稳定问题身份，表达“哪个站点、哪个对象、哪类具体问题”。归一词、核实后的canonical／意图可参与；**报告ID、周期日期和来源快照哈希只作证据版本，不放进问题身份来制造新任务**。不同语言、不同意图或不同真实问题不能强并。同义意图需真实SERP与页面证据，不仅比较字符串。
3. 一个已有页面的共同问题可关联多个受影响词；多个来源指向同一问题，共用原taskId和issue并追加来源。跨周未完成沿原ID续跑，不复制到新周占位。多个候选匹配而无法确认唯一对象时记录冲突，先核对，不随便挑一条或新建替代任务。
4. 没有已有任务且结论有实际证据时，可依本次授权新建 `kind=research|review`、`status=planned` 的诊断／研究候选及关联issue。这是新增真实问题的入口，不是绕过原任务失败、审批或研究门槛的替代任务。没有可靠关键词／市场身份时允许按schema留空并明确补证，不造ID、排名或国家。
5. 现有任务通过 `save_task` 的 `expectedVersion` CAS及稳定requestId追加证据，并在完整保留原nextAction前缀后追加`〔复盘 problemKey〕`短摘要；超过3000字符时明确未应用，不截断原文。保留原ID、weekStart、dueAt、kind、状态、主词、页面、市场、语言、brief、审批、内容版本及租约相关字段。工作流逐条操作不是跨记录原子事务；409先重读重新计算，响应不明先核对原请求与记录，不换ID重发。
6. 已有任务已经发布／验收时，只追加真实观察，不把它退回planned或冒称新制作。确有独立新问题先记录其依据和与旧交付的关系；依原审核和排期流程处理。证据／备注达到schema容量时保留准确缺口，引用可追溯产物，不删原证据腾空间。
7. 写后逐项生产读回任务／issue的确切ID、版本、保留字段和新增内容。仅本地清单、HTTP200、报告一句建议或 `save_task` 成功都不能当作正式排期已完成。

不存在Topic `priority`字段时，将优先依据保存到现有任务的nextAction／evidence，不假报字段已更新。Topic实际关系调整继续遵守[每周TopicMap复盘](weekly-topicmap-review.md)的完整图校验、写前重读和正常单行写回；SUB改父只增边，不能报告旧边已经删除。此流程不授权强行合并已发文、改原词／canonical或替换已排任务。

### 结论转任务工具

`scripts/seo-content-review.cjs`沿已有工作流接口预览／应用结论，不是排名采集器，不调用收费供应商、不改报告模板，也不自动保存正式计划或发布。工具核对已入库任务、issue、发布及历史记录，不代替实际CMS／公开页面的意图去重；调用方仍须先完成上述检查。输入清单须引用真实来源文件及SHA-256；原始数据快照与完整决策产物分别保存、分别标明，不能以生成的分析文字冒充原始证据。工具复用task／issue时完整保留原nextAction前缀，再追加本轮复盘短摘要；完整输入决策文件的真实hash及修改时间另作decisionArtifact证据，原始来源证据单列，不能只在临时preview里出现。默认只读，示例路径须替换为本次真实产物：

```sh
rtk proxy node scripts/seo-content-review.cjs --input=/absolute/findings.json --out=/absolute/preview.json
```

预览核对新建／复用／冲突、原任务字段保留及计划哈希后，将下面的`PREVIEW_PLAN_HASH`替换为真实`preview.planHash`，显式使用同一哈希应用：

```sh
rtk proxy node scripts/seo-content-review.cjs --input=/absolute/findings.json --out=/absolute/applied.json --apply --expected-plan=PREVIEW_PLAN_HASH
```

`--workflow=/absolute/all-history.json`仅用于离线预览，不能据旧本地快照写生产。应用必须重新读取生产、核对同一预览计划；来源变更或任务并发变化时重新评估，不套用旧预览。凭据沿现有`SEO_IMPORT_TOKEN`注入进程，不放输入清单、日志或Git。输入没有匹配任务又缺少新候选的周次、负责人和交付时刻时，保留明确未应用原因，不编造任务属性。

清单使用`schemaVersion=1`、真实`period.start/end/timezone`；`sources[]`提供唯一id、`kind=weekly|keyword`、绝对artifact路径、完整sha256及observedAt，finding通过`sourceIds`引用。每项finding有稳定`problemKey`，并明确`changeType=keyword_diagnosis|content_refresh|new_content|technical_review|measurement_review`，避免同词不同意图或动作强并；国家与语言成对提供，身份不明时成对留空。原任务／issue精确关联用`existingTaskId`／`existingIssueId`并附中文`linkReason`，不靠模糊同词匹配。新候选若提供keywordId，还须通过已有`SEO_RESEARCH_READ_KEY`只读核验真实词及原站点成员；无法核实时留空并保留身份补证，不编造或错绑。

## 接入原页面、博客和优化执行

正式排期前仍须原词原市场10条自然结果、前5实际打开的逐页3C、CMS／路由／canonical／在途意图去重、真实关键词身份、六项分析及E-E-A-T。未通过只保留原候选补证，不制稿／发布，不为凑额度换词或降门槛。

## 交付、效果复查与周报回流

交付验收和效果验收分别记录。实际发布后保存精确URL、真实完成时刻、内容／代码版本、来源回执和正式页核验。HTTP200或完成一篇文章不证明被Google收录或产生增长。

以真实优化／上线日为基线，在原任务追加7／14／28天到期复查、实际可比窗口、指标及证据；不将dueAt强改到原weekStart以外，也不每个复查日另建一个交付任务。后续原周报和执行流程消费到期观察，缺完整窗口时保留实际已结束天数及下次检查条件。7天是初步检查，不承诺所有页面在7天见效；低样本和长期主题按28／90日背景判断。

分别比较相同页面／查询／国家／来源口径的曝光、点击、排名、自然访问和注册，不用两个独立用户数拼漏斗，不把GA4注册／会话比当同批用户转化率。没有改善则沿原任务补证并调整；有改善仍区分相关贡献与可验证因果，不能仅以发文数量或任务结单率评估策略。

周报保持原六块、四组流量、模块占比、本周进度和下周计划。实际调整与任务关联在原归因、关键词观察和第六块表达，不新增状态列、不删改板块顺序。完整待审正文／来源哈希保存读回后先交用户；该确切版本批准后才保存已审并沿原群、机器人和幂等账本发送，原周报自动群发继续暂停。周四日报只归档不群发，也不次日补发。

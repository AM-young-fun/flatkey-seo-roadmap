三表增量维护安排为每天北京时间10:30。用户已选择沿用现有独立采集器：通过DWS读取三表，再提交已审核数据，无需新增钉钉应用凭据。仓库自身不直接拉取钉钉文档，不能将“已保存基线”表述成“服务端每日直连已接通”。采集器先确认真实表头后按稳定编号／语言／slug定位，不能以当前行号作身份：

`POST /api/keywords/source-sync`接受既有导入Bearer密钥或管理页登录会话。管理页原有JSON导入框可直接识别`kind: "source-sync"`，不用另建页面。字段完整定义在`src/lib/source-sync.ts`。

`GET /api/keywords/source-sync`仅接受已启用的管理员登录会话，返回三表已存行数、最近内容入库时间和已变更行的最近真实来源读取时间；不接受导入Bearer替代登录，不请求钉钉或排名供应商，也不刷新来源时间。来源行没有变化时严格不重写，因此这些时间不能证明最近一次每日完整检查。管理页明确展示“沿用现有采集器”，每日完整检查状态保持未确认；后续如需展示完成回执，必须独立保存完整采集运行记录，不能用现有行的`updatedAt`／`observedAt`伪造运行成功。

```json
{
  "kind": "source-sync",
  "requestId": "source-api_main-content-hash",
  "targetDomain": "flatkey.ai",
  "action": "preview",
  "sourceId": "api_main",
  "rows": [{
    "rowKey": "id-001-en",
    "completion": "PENDING",
    "publication": { "pageVerified": false },
    "keywords": [{
      "keyword": "example model api",
      "role": "PRIMARY",
      "relevance": "REVIEW",
      "reason": "需核实业务意图和对应页面",
      "pageIntentMatched": false
    }]
  }]
}
```

先逐批preview，再立即用当前stateHash作为expectedStateHash应用同一批；应用前状态变化会409，重新预览后处理。重传相同规范内容只读不重复写入；每批不超过30行以便核对。首次读取会建立来源基线，以后只保存新增／变化行；缺行、移除副词或换行排序均不删除旧关键词。不把采集时间、排名回填列、样式或每天改写的审核措辞算作来源内容变化，未变化行沿用上次规范化审核结果。

每词单独筛检业务相关性和主意图，不能把一行全部副词随主词一起通过。新模型和新词先保留；尚未完成或未核实公开页面的业务词留候选。有已完成内容、真实对应页面且逐词意图匹配的新增词才进入正式监控。HTTP200不是意图匹配证明，完整正文／canonical／语言／主词须一致；publication.verificationReason保存核验依据，pageIntentMatched逐词确认。历史人工审计、已有正式页面、保护模型和归并／停用状态不被表格覆盖；不同页面记为冲突，既有页面不自动重挂。

排名和搜索量不从协作表历史单元格同步。正式目标排名使用独立的DataForSEO SERP前100核验计划，隔周周二10:30；当前仅接入与配置，部署环境付费闸门与线上计划授权双闸保持关闭。每日三表日检只查看本系统已存状态和费用预览，任何日期均不能请求收费供应商或因计划到期自动启用付费。GSC/Ahrefs/Labs旧证据保留为历史，不能补作当次SERP名次。成功完成前100核验且本站未出现，才可标记“暂无前100排名”；待采集、失败和数据库未返回都不能作此判断。同词多个实际页面分别保存名次，关键词汇总取同一轮最佳自然名次且只计一次。

成熟词清退的唯一自动例外是外部平台证明持续无需求：读取Ahrefs Keywords Explorer的月度历史，不能用默认12个月均量、GSC零曝光或Organic Keywords未检出替代。连续至少60天或两个完整月的明确零值才进入归档复核；任一跟踪市场有正量、数据未知、新词／新模型、近期曝光点击或真实排名页面等保护信号则保留。保存实际月度数据、市场、来源URL和读取时间，达到条件才通过显式筛检归档并保留可恢复记录；权限、历史月份不足或单次0均不执行。当前没有启用付费SERP，也不调用收费声量API。

## 既有页面的逐词复核

管理页同一JSON导入入口接受 `kind: "page-audit"`，每批1–30词，只能使用登录会话。先 `action: "preview"`，从“本次导入回执”读取逐词变化与 `stateHash`，核对后以相同内容和 `expectedStateHash` 应用。回执可留存；重复同一证据不重复写入，遇人工配置变化或旧核验时间会409。

每词提供 `keyword`、`verdict`、`checkedAt`、`reason`、`evidence`，有明确结论时附 `pageUrl` 与 `httpStatus`。VERIFIED 还须实际最终页面的同址 `canonicalUrl`、HTTP200及标题/H1/正文证据，设置 READY 并补齐对应页面；MISSING 只接受404/410，旧页面移到候选并标待建设；MISMATCH 须HTTP200和具体不匹配理由，旧页面保留候选并标待重新关联；REVIEW 只保存核验记录，不覆盖既有确认。保护模型仍保留保护标记，但错误的页面关联也可根据真实证据纠正。此接口不新建、删除、停用或变更关键词池，不修改固定历史审计文件。

用户现已批准接入DataForSEO SERP及隔周周二10:30的计划机制，但明确要求暂不执行付费抓取。本次部署、只读状态检查、三表来源同步和费用预览都不能触发供应商付费请求。原SerpApi每日四国旧流程不应恢复。GSC只代表已出现曝光的查询，周平均排名不等于实时Google名次，未检出不等于确认前100之外。


## 优化完成时间与市场展示

优化表 `版本/发布时间` 作为 `rows[].optimizedAt` 导入：仅有日期时使用 `YYYY-MM-DD`，有明确时区的时间使用 ISO 8601；原始批次说明可放在 `optimizationNote`。不得用来源读取时间、数据库更新时间或 SERP 采集时间代替优化完成时间。旧采集器未发送此字段时保留已保存日期；明确传 `null` 可清除错误日期。页面显示同 URL 最新的来源优化时间，缺失则显示“来源未记录优化时间”。

管理员可通过 `GET /api/keywords/source-sync?includeRows=optimization` 查看当前已存的优化来源行，基于原记录补日期后走原有 preview/apply 流程；导入凭证不能替代管理员会话读取来源行。补录前应核对预览只修改日期相关字段。

关键词概览改为按单个国家月搜索量降序排列，条长使用真实比例。同词跨网站的需求取最大已知值，不叠加；明确零值与缺失分开，未绑定国家的 `defaultVolume` 不填入美国声量。国家筛选同时筛选关键词行和排名数据：默认按来源语种匹配目标市场（日语假名作为补充识别）；无语种词参考该国已有数据。开启“包含跨语种词”可查看其他语种在该国的已有观测；未分配国家的词仍保留在全部国家词库中。该展示筛选不更改付费采集范围或历史账本。

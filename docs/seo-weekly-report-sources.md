# 周报来源和上涨页面分析

原周四 16:30 周报按报告前置回执启动。前置终态后，用现有 Google 只读采集凭据运行 `scripts/server-seo-weekly-report-sources.cjs --date=YYYY-MM-DD --out=回执目录`。日期是原周报归档键（周四）；脚本采该键对应的洛杉矶周四至周三和紧邻上一周。复用同一输出目录内已核请求；需要刷新尚未最终出数的 GSC 时，使用独立的输出目录保留两轮原始证据。

- 用产出的 `dashboardEvidence` 和原始来源回执生成同一版五块正文与看板，连同 `sourceEvidenceSha256` 经原 `save_draft` 归档，再按确切报告 ID 读回。正文与图表使用同一观察时点。新来源使用新版，保留旧快照及审核记录。
- 保留各站 GA4 属性的真实时区。站点自然搜索会话与 Flatkey 四国、模块和页面入口沿各自过滤条件。Flatkey 首次自然搜索获客注册和模块访客占比取整段去重。其他站点或模块注册归因待核实的单元格保持缺值。
- GSC 查询包含当前可读数据，按日期回执核对首个不完整日。日报采集终态为缺口也可继续周报专用只读查询。报告显示有证据的初步点击及曝光，暂缓不完整窗口的周环比。没有返回值的单元格保留缺值。

## 上涨前三页与 AI 加推判断

从 `growingPageCandidates` 按 GA4 整周自然搜索会话绝对增量顺序核对官网已上线的 canonical，取最多三个不同页面。两期均需有该页明确值。缺基期的页面没有可核增量。每页列链接、上期至本期数值、绝对增量和生产 TopicMap 原话题；同话题可对应多个页面，无法核对时写「话题待确认」。

周报自动化依据原计划增长复盘、近 28 日和可比 90 日趋势、目标市场实际搜索需求、同页业务承接及原任务，独立撰写每页的「AI 加推建议」。写明判断和一项具体动作。资料不足时列「继续观察」及缺口。建议优先补现有匹配页面或复用原任务；正式加推沿原审批、容量和同市场 Top 10／前五页 3C。报告不自行调整排期。可另外简短保留已核验下降页面或市场，GSC 点击与 GA4 会话各用原单位。没有可核验的改动记录时，流量变化写「自然变化」。

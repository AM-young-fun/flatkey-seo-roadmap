## 新投影规则

1. 以每期原冻结成员和同一期实际采样结果为输入。原成员、原词、站点、国家、URL、runId、采集时间和全部备选观察保留；不使用今天的激活状态删除旧分母。
2. 原词只做 NFKC、首尾空白、连续空格和大小写规范化；不翻译，不做语义合并。规范化后同词跨站、跨国家只计一个数。
3. 沿用原有逐词语种证据及明确词汇证据。美国/英语、日本/日语、巴西/葡语、西班牙/西语只采用实际该国且原词语种匹配的结果。中性型号、共享术语和不可靠的纯汉字短词保留待核，不凭查询语言或网页语言判作英语。
4. 只从已有效检出前100的匹配观察里选最佳自然名次；同名次按实际采样时间、国家、站点、原词ID稳定选取。日本查到的英语排名不能改记美国；中国中文旧结果也不能改记新加坡。本历史四国读取源没有中国或新加坡观察，不凭空补两国。
5. 多 URL、多个站点的详情全部留在审计记录里，主图只计一次。各国上榜小计之和、四个排名段之和均等于去重上榜总数。
6. 明确自有品牌从校正展示层排除，原数据不删。待采、失败、未充分检出、语种待核与已确认100名外分别保留；没有来源不填0。
7. 不混用 GSC 均位和 SERP 名次。每期原范围不同，默认离散观察，不连线或计算环比。保留原有效采集数，让“语种匹配数减少”不被误读为未执行采集。

## 代码接入

- `src/lib/ranking-language-history.ts`：纯内存校正投影和逐词取舍审计。
- `src/lib/services/display-trends.ts`：复用原只读历史任务/成员查询，四国一次读取后分别计算；未调用供应商。
- `src/components/RankingTrend.tsx` 与 `GrowthHistoricalReview.tsx`：主图、国家小计、分段和历史核对表消费同一投影；旧缓存版本失效，不能把旧汇总换标签冒充新口径。
- `scripts/review-ranking-language-history.cjs`：只接受明确指定的已保存成员/任务 JSON，输出带源字节和规则文件哈希的不可覆盖审计文件；不读凭据，不联网，不写生产。
- `GET /api/seo/trends/history-export`：已发布的只读出口。仅接受上表三个固定 runId；沿用已有排名只读认证，`kind=cohort`读原冻结成员，`kind=tasks&offset=0&limit=200`按原任务ID分页。只读原存档，保留原集合哈希、runId及任务状态；cohort与tasks中的成员均共用字段白名单，只保留原 `keywordId`、`keyword`、允许站点的 `siteDomain` 及字符串 `targetUrls`，未知扩展和嵌套字段不导出，原存档不变。不返回凭据、配置秘密或原始供应商响应，也没有 POST／poll／恢复／付费路径。

离线输入须为既有 `loadSerpTrendCohorts()` 的完整输出与 `loadSerpTasks(..., start, end)` 的完整输出，或保留这两个数组的 JSON 包装。任务需有原 runId、periodKey、原 targetsJson、采样国家、checkedAt、state 及已保存 normalizedJson。不能用截断后的当前目标详情、来源未知的查询环境或按时间推测的 runId 代替。

```sh
node scripts/review-ranking-language-history.cjs \
  --cohorts=/absolute/path/saved-cohorts.json \
  --tasks=/absolute/path/saved-tasks.json \
  --start=2026-10-01 --end=2026-11-16 \
  --out=/absolute/path/historical-review
```

本次按上述固定计划逐 run 保存完整 cohort，从 offset=0 按 `nextOffset` 保存 tasks，核验原run、原期次和原查询数量后按原ID合并；未漏页，未将单页当全期。离线工具拒绝直接使用带分页或 `partial=true` 的单页响应。所有原响应字节已留档哈希，原冻结成员和任务均未回写。

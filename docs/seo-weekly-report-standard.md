# Flatkey SEO 周报标准（2026-11-19）

北京时间每周四 **16:30 开始整理，保存待用户审核的周报预览**。统一统计 `America/Los_Angeles` 上周四 00:00 至本周四 00:00，结束日显示本周三，连续 7 个当地自然日；对比再前 7 天的同星期范围。首次新周期为 **2026-11-12 至 2026-11-18**。使用 IANA 时区计算夏令时，不能写死 UTC 偏移。洛杉矶周三结束对应北京时间周四冬令时 16:00、夏令时 15:00。

周四 16:30 是开始整理时间，不保证数据已经到齐。GA4/GSC 延迟时保留固定周期并标「待更新」，逐项列实际时区、截止日和覆盖；缺数不填 0。只有两个周期都有完整且同口径的来源数据才计算环比。其他时区的 GA4 日桶、UTC 账户注册和 GitHub 来源只能按实际口径单列，不能直接当成洛杉矶同期指标；没有对应证据就标缺失，不改 GA/GTM/GSC 设置。

先用现有 `POST /api/seo/digest` 的 `prepare` 保存版本，再按确切 `reportId` 使用 `read_saved` 读回，确认 `reportPeriod`、时间窗、来源覆盖、生成时间和哈希。向用户提供可审核版本与缺口；用户对具体版本明确批准前不发送。原周五 11:30 周报自动发送任务已暂停，日报沿原流程。旧快照及其周二／周五周期保留，不静默重算、不拿旧周期与新周期混比。

周四旧文轮查、下周候选以及周五 10:10 正式排期保持各自日程。周四初稿中的下周安排按真实状态写候选／待定稿，不把候选写成已排期；后续数据或计划补齐时另存修订预览，仍供用户审核。下一周优化清单的工作周期独立于流量统计周期。日报保留明细，周报先讲结果、原因证据和下一步。

## 展示顺序

首屏：一句结论 → 自然搜索访问与注册 → 一张可切换趋势。下面是最多 5 项「本周优化清单」。搜索表现、页面贡献、关键词变化、技术异常和原始证据收进对应展开区。缺数据时仍交付已核实部分，并明确未完成项，不用大段通用SEO知识替代业务结论。

每周结论回答：本周SEO结果如何、变化主要来自哪里、有何证据、本周最该做哪几个动作。关键词优化优先级综合业务相关性、当前机会、竞争/意图匹配、工作量和数据新鲜度，不能只按搜索量排序。每月再复查长期增长、内容覆盖和技术趋势，避免每周对短期噪音过度调整。

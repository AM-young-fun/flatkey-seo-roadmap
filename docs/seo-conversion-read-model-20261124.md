# 自然获客注册与30天首次付费只读模型

新入口为 `GET /api/seo/growth/conversion`，复用现有登录或SEO只读认证；限定站点、国家及已结束的来源窗口，不触发Google、计费、采集或任务。日报、周报和总览使用同一只读投影；新报告在原业务板块补充GPU承接与API转化，不新增报告板块。当前报告为v9五块，GitHub保持独立任务和原历史，不再进入新报告生成或复盘。

API注册率只在“同一来源窗口、首次自然搜索获客、进入时尚未注册的合格去重访客”与首次有效账户注册身份完整对齐时计算。会话数、GA4全部用户或事件次数都不能替代合格用户分母。重复注册只保留全历史最早有效注册，一人只进入原注册cohort。

注册率分子为当期合格访客中实际首次注册的独立用户，单列 `eligibleFirstRegistrations`；当期全部自然获客首次注册人数 `firstRegistrations` 仍保留前期访客回流注册，不能拿全部注册N混除当期合格访客。30天首次付费cohort继续保留全部原注册N。

30天首次付费按同一原注册cohort计算，原注册人数N冻结。支付须能关联稳定账户身份，并有完整成功收款历史，以确定真正首笔成功非测试、非赠额且金额大于0的付款；不是窗口内首笔或续费。观察范围为注册时点起720小时，右端点不包含。成熟、未满30天、混合批次分别给出；未成熟可显示已证实进展，最终率保持空值。身份缺失、账本延迟和关联失败均保留原N，不缩小分母，也不把缺源当0。

GPU业务承接独立显示有效询盘、报价、成交，按各阶段真实业务ID去重。API注册/首付不能当GPU成交；`gpu_rental_success`等GA事件也不能代替业务阶段证明。两类来源就绪状态独立。

当前正式存档 `GA4_BUSINESS` 的会话自然搜索归因、GA4 reporting identity和可观察注册漏斗，不足以证明进入时注册资格、全历史首次账户注册或完整首次收款。本实现保留其存档引用，明确 `unavailable/null`，没有把旧事件数改标签冒充新付费率。合格只读证据须有明确来源范围、观察时点、覆盖及身份不变量；本轮只加入读取 `SEO_CONVERSION_EVIDENCE` 的严格合同，没有创建入库、埋点、产品后端或支付写接口。

输出只含合计、比率、cohort日期和内部存档引用，不返回账户、访客或交易身份。新生成报告把该快照和模板版本纳入ID/hash与待审/已审读回，正文不能改值或移除缺源说明却继续显示旧结构。原存报告没有v9标记时保持原渲染与原哈希逻辑。

定向验证覆盖首次注册不变量、重复收款去重、缺身份留N、支付缺源不0、720小时边界、未成熟进展、GPU/API分离、旧GA漏斗拒绝、GET鉴权与严格查询、五块模板、连续Markdown表格及冻结快照一致性。未新增任何Google/GA/GTM/GSC变更，未恢复已撤回的支付埋点任务。

模块占比依v9恢复在原模块表与原正文位置：同区间全站去重访客为分母，模块可重叠，不相加。复用已有确切周期的模块来源快照或原正常来源包，不逐日相加，也不调用新Google查询。缺可靠分母时正文短说明，图表保留空值；原历史无v9标记继续旧访客量表。模块来源、正文、投影、hash及待审/已审版本一起冻结，补齐来源须同时更新同一版本的正文，不能保留旧“未齐”正文却展示新比例。新周报取数整理时点使用北京时间，统计周期仍为洛杉矶。

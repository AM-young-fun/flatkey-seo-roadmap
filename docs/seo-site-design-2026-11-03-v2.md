# Flatkey SEO 站点整体页面设计文档

在线文档：https://chatgpt.com/space/page_b569afb46dd48191a2cf2dee9e395e3a

本方案将Flatkey SEO站点组织为“每日可查记录、周内可看累计、每周可读总结”的工作流程。首页必须保留业务词库关系图，同时呈现流量变化和优先行动。主导航为“总览、页面效果、关键词机会、周报总结”，数据管理放在右上角次级入口。

版本：2026年11月3日第二版修订。已有全站及原四组每日记录、日采集任务和周报定时任务作为基础；本版重新设计每日记录、本周累计、周报总结、自由时间选择和业务页面分块，并补充专业SEO分析规则。逐URL采集、分钟级监控及新增业务转化等模块属于建设方案，可用状态以实际接通为准。

# 二 整体导航与通用布局

主导航：总览、页面效果、关键词机会、周报总结。右侧提供数据状态、数据管理和账号入口。首页增加每日记录直达及查看本周周报入口；周报不再藏在历史链接中。原页面链接保留可访问，迁移时建立清晰的导航映射。

各页面共用可自由选择的日期、站点和市场上下文。默认站点为Flatkey；国家、语言、设备仅在对应来源支持时生效，并说明筛选的适用范围。点击分类、具体URL和关键词时传递条件，返回后恢复筛选、滚动和图的状态。

时间分为实时活动、日归档及区间报告。首页默认最近30个已结束日，可自由选择起止日期或查看本周累计。GA4日数据按属性时区America/Los_Angeles归档，采集时间显示北京时间；GSC与排名标记自身可用日期。周报保留周五至周四周期，同时支持独立生成自定义区间总结。

## 自由选择时间

全局日期控件提供今天、昨天、近7天、近30天、近90天、本周、上周、本月及自定义起止日期，支持跨月跨年。起止日包含在区间内，显示实际天数和时区；选择今天时标注“日内暂定”。

对比可选关闭、上一等长周期、去年同期及自定义区间。不同天数的区间显示天数与日均值，不把总量差直接解释为增长率。没有历史证据或尚未返回的数据标待补采，不补零；超出实际留存范围时说明可用边界，不静默缩短所选区间。

指标卡、趋势、页面列表、详情和关键词分析继承所选区间。每日粒度为基础，长区间可按周或月展示；CTR按总点击除以总曝光计算，人数按整段区间去重。筛选保存在链接中，可分享同一视图。

各来源分别显示可用截止日。历史排名取结束日当日或之前最近一次有效观测并显示真实采集日，无对应记录则未知。搜索量显示来源月份，不当作所选区间真实访问。实时视图支持分钟数据实际留存范围内的起止时间，超出范围引导到日归档。

## 核心指标卡

首页展示四张卡：自然搜索访问次数、Google搜索点击、SEO去重注册、GPU有效询盘。指标卡下方设置实时活动条，展示最近5分钟活跃访客、近30分钟SEO入口访问和注册，点击进入页面效果的实时视图。每卡包含当前值、上一等长周期值、变化和数据截至日期。询盘等尚未接通指标显示“待接入”；数据未补齐显示“待补采”。

自然搜索访问采用本次会话的Organic Search口径。已有首次SEO获客人群数据保留为独立视图，名称明确。注册采用核验后的自然入口漏斗，GPU询盘仅统计已核验SEO来源的有效线索，按线索去重；两者不会混成一个转化总数。

## 趋势与本周行动

每日趋势默认最近30个已结束日，可切搜索点击、注册及询盘，也可自由选择起止日和比较区间。今天的数据用暂定曲线区分。本周累计使用当前周五至最近已齐全日，对比上周相同天数。图上标记实际发布及优化日期，可进入对应URL及改动，各来源显示单位和截止日。

右侧展示最多三项优先行动，供每日检查和周报下周计划共同引用。每项包含URL或关键词、问题、证据日期、建议动作、优先原因与当前进度。证据不足时少列条目。任务完成与效果改善分别确认，周报不会把计划或发布动作写成已经带来的增长。

## 新页面与排名摘要

新页面观察展示最近上线的五项：页面名称、上线天数、搜索点击、自然访问、注册或询盘、当前观察状态。点击进入页面详情。

排名摘要使用固定的重点业务词集合，展示Top3、Top10及变化；同时标明市场、跟踪词数量和采集日期。新增跟踪词与同一批词的排名提升分别呈现，避免把覆盖扩张写成排名改善。 自选历史区间时取结束日或之前最近一次有效观测，无历史快照则未知，不用今日排名冒充历史。

# 四 首页业务词库关系图

关系图位于首页第二屏顶部，作为全宽主模块。顶部提供“业务词库关系图”直达入口。桌面建议高度560像素，移动端建议高度420像素，支持展开大图。

## 保留内容

保留业务词与主题的关联关系、关键词搜索、缩放和悬停查看。节点面积继续表达已知月搜索量，颜色表达实际排名状态；图例说明单位、市场和日期。没有实测排名的节点继续明确标为“尚无实测排名记录”。

按现有跟踪市场提供筛选，当前为美国、日本、西班牙和巴西。四国汇总的搜索量合计与四国最佳排名分别标注，不能显示为全球搜索量或平均排名。搜索量缺失显示未知，最小节点大小不代表实际搜索量为零。

## 新增交互

点击节点打开右侧关键词详情：所属业务主题、各市场搜索量、各市场排名与采集日期、关联目标页面、优先级及原因、当前优化任务。可继续进入关键词详情或具体页面。

图中不直接显示“该关键词带来注册数”，因为现有页面注册无法直接分摊到单个搜索词。新增的建议关系明确标记待确认，不与已有业务关系混用。

筛选、搜索和关闭详情后保留图的缩放及选中状态。大量节点时按主题聚合或渐进加载，完整词库仍可搜索；任何抽样或筛选都显示可见数量和总数。 自选日期影响图内排名快照与效果字段；业务关系默认显示当前维护版本并标明版本，搜索量保留来源月份，分别说明时间含义。

# 五 每日记录与本周累计

## 每日记录看什么

首页趋势下方提供日期条和“查看每日记录”，展示每个日期的完整、部分完成、待补采和修订状态。点击日期展开当日明细，保留返回原趋势的入口。

| 内容块 | 当日内容 |
|---|---|
| 全站指标 | 自然搜索访问、Google点击、去重注册及已接通的业务转化 |
| 分类表现 | 首页、模型页面、提示词页面、GPU、博客及其他的自然入口与业务结果，模型内细分列表与详情 |
| 具体页面 | 该日增长、下降和新上线URL，附目标词及业务分类 |
| 实际改动 | 当日真实发布与优化记录，引用发布或任务证据 |
| 数据状态 | 来源、采集时间、覆盖范围、缺项和修订记录 |

每天北京时间10点30分采集最新已结束日，先补停机以来漏掉的日期，再复核近三日。有效部分先保存，某项缺失不会阻止其他已验证指标留存。只有必需项均真实取得、保存且回读一致，才标为完整。实际改动没有记录时显示未记录，不自动编造每日工作内容。

每日原始指标与解释分别保存。日数据修订保留旧版本、原因和实际采集时间；同一天可以有补采版本，图表使用适用口径的最新有效证据。

## 本周累计看什么

首页“本周累计”展示当前周五至最近已齐全日的累计结果、每日曲线、主要增长及下降页面，以及尚未补齐的日期。比较对象为上一周相同天数，不能把三天累计与整周直接比较。

周访客及注册按整段区间重新去重；未取得区间去重结果时标待核验，不累加每日人数替代。点击与浏览次数只在相同来源、口径和互不重叠的日区间下汇总，CTR按总点击除以总曝光计算。页面组之间不直接相加为全站人数。

页面顶部同时显示当前周周期、已覆盖日期、各来源截止日期和最近更新时间。本周累计用于周内观察，进入周报后显示为“本周草稿”，不会覆盖历史已保存周报。

# 六 周报总结

“周报总结”作为第四个主导航。进入后默认展示最近生成的一期，顶部可切本周草稿及历史周报。首页底部展示本周结论预览和完整周报入口。 提供自由起止日期、对比区间和“生成所选区间总结”，自定义报告与固定周报分别保存。

## 本周总结必须包含的内容

| 模块 | 内容要求 |
|---|---|
| 一句话结论 | 本周整体变化、主要贡献或下降原因线索、最优先处理的问题；无法确认因果时写待验证 |
| 整体结果 | 自然访问、搜索点击、去重注册及已接通的业务转化，对比上一完整可比周期 |
| 分类效果 | 首页、模型页面、提示词页面、GPU、博客及其他分别变化，模型内下钻列表与详情，数字链接URL和日期 |
| 新页面与优化 | 实际上线和改动、上线后天数、已观察效果、仍待观察的事项 |
| 关键词变化 | 固定跟踪词集合的变化及高潜机会，新增词与原词提升分别说明 |
| 问题与缺口 | 技术异常、数据缺失、尚未核验的归因或效果，列出下一步核查 |
| 下周行动 | 按优先级列3至5项，包含页面或词、理由、动作、验收点与负责人；负责人未知则待分配 |

本周完成的工作来自实际发布记录、优化任务和采集证据；任务状态、页面上线及效果达成分别表述。周报总结引用对应每日记录、页面和关键词证据，点击数字能够查看范围与来源。样本不足时明确待观察，不生成确定的增长原因或精确收益承诺。

## 周期与生成规则

周报周期沿用周五至周四，每周五北京时间10点10分生成当时的数据快照和总结，原有每日10点30分任务保持。周报读取已保存记录并核对截止日缺口，按需补采整周去重指标，不等待当天10点30分任务才判断完成。

GA4属性时区与北京时间不同，周五10点10分时属性当地的周四可能尚未结束，GSC等来源也可能尚未齐全。因此页面必须显示各来源实际截止时间；当期未完整时明确标“周报快照，数据待补齐”，只描述当时已取得的阶段表现。各来源齐全并回读核验后另存核验修订版，保留原快照及生成时间。

生成状态为“本周草稿、周报快照待补齐、已核验、生成失败”。本周草稿随日数据更新；历史周报保存版本，修订不会静默覆盖原文。生成失败时保留上期周报，并提示本期状态，不能拿上期内容冒充本周结果。

## 周报生成方式

先读取本周期的每日记录、实际上线与优化记录、页面效果和排名证据，检查覆盖与口径；再生成结构化指标和文字总结；最后保存版本并验证页面回读。周报使用整周去重结果或明确的阶段结果，保存数值和来源快照，使后续日数据修订不会悄悄改变旧周报。

## 自定义区间总结

可对任意有数据的起止日期生成总结，复用周报的整体结果、分类表现、页面工作与效果、问题和优先行动结构。生成前显示所选区间、比较区间、实际覆盖日和各来源截止日；未完整区间明确标阶段结果。

自定义报告保存筛选条件、指标快照、来源与规则版本、生成时间，可按日期查找并返回分析视图。它不覆盖固定周报，也不改变周五定时任务。

# 七 页面效果列表

页面效果按业务类型分块：一级标签为“全部、首页、模型页面、提示词页面、GPU页面、博客及其他”。第二行提供“全部状态、新上线、已优化、需关注”状态筛选，以及国家、语言和设备。业务分类与状态相互独立，可在任一分类内继续筛选新页面和异常页面。

## 页面分类与分块布局

| 一级分类 | 二级分类与范围 |
|---|---|
| 首页 | 主站首页及各语言首页，逐URL保留语言 |
| 模型页面 | 模型列表、单模型详情、经核实的模型API专题落地页 |
| 提示词页面 | 提示词列表、分类与详情；嵌在模型路径下的提示词详情也只归此类 |
| GPU页面 | 已上线的算力、机型和相关业务落地页，具体路由核实后登记 |
| 博客及其他 | 博客与其他业务落地页分别可筛选，未分类页面进入待归类 |

每个URL只有一个主分类，可有多个主题标签。不同语言URL独立记录，再用内容家族关联；不因路径嵌套把提示词详情同时计入模型详情。未上线的规划页面不计为已上线页面。

每块顶部展示已纳入页面数、自然入口、Google点击及已接通的业务结果；下方为当前分类趋势和具体URL列表。首页提供相同分类的紧凑摘要，点击进入页面效果并继承日期和市场。模型页面继续下钻列表与详情，提示词页面下钻列表、分类与详情。

原四组历史数据按原规则留存；新增首页与API专题等范围建立新分类版本，重新查询可回补历史，不把旧四组数字直接改名为新分类。显示已归类、待归类及排除数量，业务分类覆盖范围可核验。

| 字段 | 展示规则 |
|---|---|
| 页面 | 标题、具体URL、分类和语言 |
| 上线或优化时间 | 实际发布时间及最近优化时间；只有发现时间时明确说明 |
| 搜索表现 | 曝光、点击、CTR和平均位置，来源GSC |
| 自然访问 | 当次自然搜索入口会话及对应访客，来源GA4或实时采集 |
| 业务结果 | 去重注册、API激活或有效GPU询盘，按页面业务展示 |
| 变化 | 对上一等长周期，附绝对变化；基数为零或不足时不生成误导性百分比 |
| 状态与动作 | 待观察、待补采、需核验或可执行的优化建议 |

列表默认按需关注程度和近期变化排序，可切流量、点击及上线时间排序。点击整行进入详情，URL提供单独的访问入口。每行展示数据新鲜度，零流量与采集故障明确区分。

各业务分类的用户和注册可能重叠，不能相加为全站去重人数。列表按所选完整区间去重，不累加每日人数；入口效果与浏览辅助效果分别展示。

# 八 具体页面详情

详情顶部展示标题、URL、分类、语言、上线日期、最近优化日期及目标市场。下方分为效果、搜索词、改动记录和优化任务四块。 面包屑显示主分类和子类型，详情继承日期与对比条件，返回恢复原分类和列表位置。

效果区展示该URL的搜索曝光与点击、自然入口访问、相关业务转化及时间趋势。实时活动与日归档分别展示。默认注册归到同次自然搜索访问的落地页，其他浏览页面的辅助效果另列。转化率使用同一漏斗的入口人数作分母；官网到console的身份与会话连续性核验完成后，才展示正式转化率。

搜索词区展示GSC可识别查询、点击、曝光、CTR、平均位置和对应国家设备；实测SERP排名放在独立字段。数据不足或匿名查询不强行分配到已知关键词。

新页面按上线后第7、14、28天记录结果。上线前显示不适用，首次被发现不等于当天上线。已优化页面比较优化前后等长、同星期区间，条件允许时参考未改动页面，并保留其他活动和改动的时间标记。

改动记录保存实际改动、时间、关联任务和负责人。任务完成与流量改善分别验证，发布成功不等于SEO目标已经达成。

# 九 新页面自动发现与建档

页面清单以生产环境公开sitemap为主，发布成功记录提供准确上线时间，GA4与GSC出现的URL用于补漏。

1. 首次接入生成历史基线，不把全部存量页面标成新上线。

2. 生产发布成功后立即登记相关URL；CMS内容发布通过发布记录登记。

3. 服务端每15分钟读取sitemap索引及全部子sitemap，保存成功快照并比对新增URL。

4. 新增URL核验实际响应、跳转目标、canonical和索引声明，再归类并纳入监控。

5. 提示词详情等未完整进入sitemap的页面，由发布目录、CMS或业务数据源补齐。

6. sitemap抓取失败、局部缺失或临时下线不会删除历史档案；确认后标记重定向、下线或不参与SEO。

档案字段包含URL、规范URL、页面组、语言、发现来源、首次发现时间、实际上线时间、最近优化时间、目标词、目标市场和状态。实际上线时间未知时保留未知；lastmod作为修改线索，不直接当首次发布时间。

去除跟踪参数和重复URL，保留有实际内容含义的参数及独立语言页。重定向关系可追溯；staging、本地预览、console及非内容接口不进入官网SEO页面总量。无需曝光的页面可以保留在业务台账中，SEO统计注明是否纳入。

# 十 分钟级实时监控

新增官网事件采集和服务端汇总，页面每30至60秒刷新。事件到看板的设计目标约1分钟，具体时效在接入后验证。持续采集在服务端执行，现有每日任务继续负责完整日归档与补缺。 用户可在实际分钟数据留存范围内选择起止时间，历史范围不足时说明边界；实时归因维持暂定状态。

| 实时内容块 | 信息 |
|---|---|
| 当前活动 | 最近5分钟活跃访客、近30分钟SEO入口会话、浏览次数、注册事件及去重状态 |
| 活跃页面 | 具体URL、页面分类、SEO入口访问、浏览、活跃访客、最近事件时间 |
| 新页面状态 | 上线、采集正常、首次访问、首次SEO访问、首次注册或询盘 |
| 异常 | 重要页面404或5xx、采集中断及有足够样本后的流量明显下降 |

只接收生产官网与获准的注册链路事件，支持单页应用路由切换。事件标识去重，累计浏览和新增访客分别统计；路径过滤跟踪或敏感参数，不保存表单正文。既有埋点与新增事件避免重复上报。

来源按本次访问判断，广告标记优先识别，搜索引擎来源辅助判断。确认为自然搜索的访问进入实时SEO指标，未知来源保留待归因，后续由GA4日数据复核。实时数据标明暂定及最后事件时间；GA4实时接口不能替代完整逐URL和会话渠道采集。

异常先在站内呈现。刚上线零流量显示待观察；采集故障显示中断。只有在足够样本、合理对照和连续异常条件下才提示流量下降。其他通知渠道另行配置，避免短时波动反复提醒。

默认展示本周优先优化，提供全部关键词、已优化和研究词筛选。保留现有词库、分市场排名、目标页面及任务记录，完整排名趋势在本页展开。

每项显示关键词、市场、目标URL、曝光与点击、GSC平均位置、实测排名、搜索量及来源日期、建议动作、工作量、优先原因与证据可信度。缺少关键数据时进入待核验，不硬算精确分数；不足十项就展示实际条目数。

# 十四 专业SEO分析与质量规则

## 分析目标与信息层次

总览先回答整体增长、哪些页面贡献变化、最值得做什么；页面效果回答哪个URL有效、何时上线或优化、下一步怎么改；关键词机会给出有依据的优先级；周报把本周结果、实际工作和下周行动串起来。专业化依靠口径、证据和可执行性，不依靠首页指标数量。这个取向参考[Ahrefs的SEO报告方法](https://ahrefs.com/blog/seo-reporting/)。

| 层次 | 核心指标 | 查看位置 |
|---|---|---|
| 业务结果 | SEO去重注册、已接通的首次成功API调用、有效GPU询盘与付费 | 总览摘要、页面详情、周报 |
| 获客与发现 | 自然入口会话、Google点击、曝光、本站非品牌查询表现 | 总览、页面分类与详情 |
| 页面与关键词 | CTR、GSC平均位置、实测排名、目标词覆盖、新页面阶段效果 | 页面详情、关键词机会 |
| 诊断与质量 | 索引状态、技术异常、数据覆盖及来源新鲜度 | 页面效果中的需关注、数据状态 |

未接入的指标显示待接入；页面数、搜索量和排名属于解释信号，不能替代注册或有效询盘。业务漏斗的分母、去重对象、归因范围和观察窗口必须随指标可查。

## 搜索表现与站内行为并排分析

GSC负责Google搜索曝光、点击与查询，GA4负责站内访问及行为。对比Google搜索时，将GA4限定为会话来源google且媒介organic，并尽量对齐日期、国家和设备；所有搜索引擎的Organic Search保留为另一独立范围。点击与会话允许正常差异，不做强行配平。这一拆分依据[Google的GSC与GA4联合分析指南](https://developers.google.com/search/docs/monitor-debug/google-analytics-search-console)。

页面URL分别保留实际访问地址、声明canonical和已观察到的Google规范URL。匹配关系可追溯；跨语言URL不会简单折叠为同一页面。广告、邮件、社交和推荐来源单独归档；同一用户过去通过SEO获客，之后从广告进入，不因此把本次广告会话归为SEO。

注册的默认分析对象为当次自然入口及其可核验转化链路。首次SEO获客人群另列，不能混入当次SEO访问趋势。搜索词数据不能识别到具体注册用户，不生成“某词精确带来几个注册”的结果。

## 品牌与需求拆分

关键词标签至少区分“本站品牌词、模型厂商品牌与型号词、泛需求词、未识别”，标签规则可编辑并保存版本。例如Flatkey及其核实变体属于本站品牌，OpenAI、DeepSeek、NVIDIA等不自动算本站品牌。混合词按明确规则归类并允许人工纠正。

展示本站品牌与非本站品牌的已知查询曝光、点击及变化，旁边保留全站总量与未识别边界。原生GSC品牌筛选可用时作为辅助证据；不可用时使用本项目词典，并明确它与Google自动分类可能不同。[Google品牌查询说明](https://developers.google.com/search/blog/2025/11/search-console-branded-filter)提供分类参考。

匿名和未返回查询不能分配到已知词。查询维度下的品牌比例标为“已识别查询中的占比”，不暗示覆盖全部搜索流量。

## 页面生命周期与同龄对比

每个页面记录实际发布、首次发现、首次观察到已索引、首次曝光、首次点击、首次SEO转化的时间与证据。“首次观察到已索引”只表示本系统第一次看到该状态，不冒充Google真实收录时间；最近抓取时间也不等于收录时间。索引诊断参考[Google URL检查说明](https://support.google.com/webmasters/answer/9012289?hl=en)。

新页面按上线后第7、14、28天观察，可按发布批次、主分类、语言和目标市场比较同龄效果，避免拿上线两天的页面和成熟页面直接比总量。指标同时显示实际覆盖天数；缺数不填零。存量页面只有发现日期时不参与依赖真实上线日的同龄排行。

同主题不同语言页面通过内容家族关联，保留各语言的独立URL、市场、canonical和hreflang检查结果；设计遵循[Google多语言与多地区站点指南](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)。

## 关键词机会必须可解释

机会先通过业务相关、搜索意图、国家语言、目标URL和样本检查，再考虑位置约4至20、已有曝光但CTR偏低、需求有证据却缺合适页面等候选情形。GSC平均位置与固定条件下的SERP实测排名分列，不当作同一指标。

CTR机会优先对照本站同市场、设备、位置区间及相近意图的历史基线，并显示观察窗口、曝光量和可比性；没有足够基线时标待积累，不套统一行业CTR阈值。预计新增点击使用区间与明确假设，和实际结果分列。

优先级展示商业价值、提升空间、可行性、工作量和证据可信度的具体依据。每条机会必须有目标URL或缺页说明、建议动作、验收点和复核日期；证据不够时待核验，不用精确小数评分掩盖不确定性。

同词出现多个URL仅提示“内容重叠候选”。结合相同市场和意图、排名URL是否交替、点击与位置是否受损后再判断；不能自动要求合并或删除页面。外部竞品与链接差距可在后续接入，第三方流量及搜索量标估计值，并显示市场和日期，不混入本站实测流量。

## 流量下降与技术问题诊断

在页面效果的“需关注”中提供排查入口，先检查数据是否齐全，再按页面、查询、国家和设备定位变化。异常阈值结合流量规模、同星期基线、持续时长和波动范围；小样本不发确定性下降结论。

| 观察到的变化 | 优先核查 |
|---|---|
| GSC与GA4同时缺数或突变 | 来源处理异常、采集失败、时区及规则变化 |
| GA4下降而GSC相对稳定 | 埋点、同意设置、跨域链路、落地与会话归因变化 |
| 曝光明显下降 | 需求季节性、索引与可抓取性、排名覆盖及页面变动 |
| 曝光接近而CTR或点击下降 | 查询与位置结构、设备市场变化、搜索结果展示及标题匹配 |
| 自然入口稳定而注册下降 | 注册埋点、注册链路、服务可用性及人群结构 |

以上为排查路径，不自动判定原因。页面输出“已观察事实、待验证解释、下一步核查”三部分，并链接证据。算法更新与同期发布仅作为时间注释，不能仅凭同日发生断言因果。排查依据参考[Google搜索流量下降诊断](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)。

技术检查并入页面详情和需关注列表，展示响应码、重定向、robots与noindex、canonical、hreflang、sitemap覆盖、内部断链及可接入的页面体验结果。每个问题说明影响URL、最近检查时间、重要程度、建议动作和修复后复核。以重要页面和新上线页面优先安排检查，遵守接口配额；没有检查记录就显示未检查。

## 优化效果与业务质量验证

实际发布和优化记录标注在趋势上。前后比较采用同星期、等长窗口，并查看市场、设备、季节需求、投放及其他同期改动；条件允许时使用未改动的可比页面辅助判断。样本不足或观察期过短时继续观察，不把同时增长写成已证实的优化收益。

模型业务可逐步接通“SEO入口、注册、创建密钥、首次成功调用、付费”的同一人群漏斗；GPU业务可接通“SEO入口、询盘、有效线索、成交”。事件、去重和跨域身份核验通过后才展示对应转化率，未接通的后段不估算。新页面与高流量页面的价值由真实业务结果共同判断。

## 数据可信度与实现边界

数据状态展示来源、口径与规则版本、统计时区、可用截止日、成功及失败日期、覆盖范围、最近采集时间，以及已知阈值、采样或查询遗漏。界面可查看差异原因；异常点保留并标注，不为了平滑曲线删除。

GSC全站总量、页面明细及查询明细分别保存。接口分页有助取数，但仍受返回范围和匿名查询限制，明细合计不保证等于全站总量；没有返回的词不记为零。按日分页、记录行数与请求范围，遇到限制时显式标明覆盖边界。依据见[Search Console导出与接口限制](https://support.google.com/webmasters/answer/12919192?hl=en)及[性能数据提取指南](https://developers.google.com/webmaster-tools/v1/how-tos/all-your-data)。

实现优先复用现有数据库、日采集、缓存和周报流程，保存来源记录与报告版本，按口径构建区间聚合。看板刷新读取已采数据，不触发新的付费排名查询。达到当前接口或存储边界后再评估批量导出等方案，不把新增付费基础设施设为首版前置条件。

自动总结读取已核验的结构化数据及真实工作记录，保留引用和数据快照。生成失败、待补采、待核验与完整结果明确区分；结论、任务完成和业务效果分别展示。

# 十五 实施分批与验收

第一批交付全局自由日期和对比、首页每日趋势与本周累计、每日记录和独立周报总结，完整保留业务词库关系图，并明确业务分类与新旧口径。第二批建立生产URL台账、分类页面效果和详情，接入GSC、品牌拆分、新页面同龄对比和机会证据。第三批接入分钟级监控、注册与业务激活链路、技术异常和优化复盘。持续复用现有日任务与周报任务；新增能力按真实接通状态展示。

验收要求：

- 首页始终可见业务词库关系图模块，搜索、缩放、悬停有效，详情可返回原位置。

- 节点颜色、面积、市场汇总和未知排名的含义清楚，原业务词库和关系不丢失。

- 全站、业务分类和单URL可互相下钻，模型与提示词子类型清楚，日期与市场条件持续保留。

- 存量页面不被误判新上线，实际发布时间与发现时间分列，失败快照不造成批量下线。

- 广告访问不进入已确认SEO指标，未知来源不强行计入自然搜索。

- 自然入口到console的注册链路、去重和漏斗分母核验通过后才展示正式转化率。

- 新页面可查看上线后7、14、28天效果；优化前后使用可比区间。

- 实时刷新不重复触发付费排名或搜索量查询，不把事件重传计为新增。

- 关键词机会有具体URL、原因、动作、工作量和证据日期，未采集不显示成无排名。

- 手机可操作，图表有明细替代，采集失败与真实零可分辨。

- 任意已留存日期都能查看指标、采集时间与来源，缺失日标待补采；原四组与新增分类的数据版本可分别核验。

- 本周累计使用已齐全日与上周等长区间，明确截止时间；周报提供完整总结和可追溯证据。

- 周五10点10分快照与后续核验修订分版留存，历史周报及已有日数据不丢失，现有定时任务无重复创建。

- 自定义起止日期和对比区间在指标、趋势、列表与详情间一致；今天标暂定，越界和缺数不伪装为零。

- 自定义区间总结与固定周报分开保存，保留条件、截止日、指标快照和修订。

- 品牌词、CTR机会、页面下滑与优化结论均可查看证据和适用范围；未识别查询不硬分配。

- 技术问题显示影响URL和最近检查时间；页面新增、分类变化及优化前后对比可复核。

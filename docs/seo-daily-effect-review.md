- 在原每日北京时间 10:30 `seo-10-00` 内串行执行，保留原热点、技术、GSC、404 和 PSI 职责及原配置，不另建 job、heartbeat、cron 或观察任务。

- 从生产平台读取跨周历史发布、正式验收及关联原任务，不只读本周计划，也不套“未完成交付任务”领取过滤器。已结单的 verified／observing 原任务仍能产生效果观察；首次发现日期不能冒充上线日。扫描不全须写覆盖及截断，不能声称无到期项。

## 到期窗口

每个观察键由原 taskId、精确页面／语言／市场、真实上线或实质优化基线版本和 7／14／28 天阶段组成，不能使用检查日或报告 ID 制造新任务。GGUF 沿 `seo-20261116-content-modelfit-gguf`，首次上线为 2026-11-23；同日控件样式修正不重置观察周期。原 11/30、12/07、12/21 为目标观察日，不保证上午数据已经闭合。

分别按实际 GA4 属性时区与 GSC 来源日界选择完整已结束日。上线当天为不完整日时，从下一个完整来源日开始累计 N 日；保存真实 publishedAt、属性时区、目标阶段、窗口起止、已结束天数、来源最新可用日和实际检查时刻。来源时区未知不得套用机器时区。上午 10:30 时窗口可能尚未结束，记录未闭合并在后续原每日轮次补齐，不提前计为完整阶段。

优化页面使用改前与改后等长且同口径完整区间，排除改动当天；7／14／28 天自然保留星期结构。新页面没有改前行为或排名时写不适用，不能将未上线页当作零流量基线。可补相邻等长的已上线窗口，但不把累计 14 天与累计 7 天相除当环比。保留其他内容版本、活动及数据覆盖差异，不将相关变化冒称本次改动的因果效果。

## 三类实际证据

1. **收录**：复用授权 GSC URL Inspection／索引采集回执，保存被检查 URL、Google 规范页、索引状态、来源更新时间和覆盖。HTTP 200、sitemap 存在、查询成功都不等于已收录。缺权限或无该 URL 样本明确留缺口，不改索引设置或请求收录。
2. **排名**：读取原词、原市场语言、精确 URL 的已有排名观测和 GSC 查询／页面平均位置，来源分别列出，保存供应商日期、维度、搜索类型和窗口。未采集、失败、未返回、确认深度外及未收录分别记录；没有观测不能写掉榜／排名 0。GSC 平均位置不能冒充某日精确关键词名次。
3. **自然流量**：读取已有页面级 GA4 自然搜索会话／用户及 GSC 点击、曝光、CTR，使用可比完整窗口。GA4 与 GSC 分列，不混加会话与点击；用户、比率沿整段真实口径，不能把逐日去重用户相加。国家、设备、查询或来源切片不能相加代替整段指标。缺行不填 0，仅来源明确的真实 0 才保存 0。

只使用已有授权只读渠道、免费接口额度及现有缓存；不启用暂停的 DataForSEO、不补跑付费 SERP、不增加分页收费、国家词量或预算。不以观察为由增加 PSI 请求或重跑性能测试。资料不足先保存已有事实与限制，不要求重新制作原页或重取研究 Top10。

- 使用现有支持的 task.evidence、nextAction 和原每日 run 回执，保留原标题、词、市场、语言、URL、dueAt、weekStart、内容版本、交付状态、审批和发布历史；不虚构 observation 字段、stage 或优先级字段。结单交付不退回研究／制作状态。
- 先读原任务最新版本、同阶段证据和并发状态，遵守原每日任务的有效 run／租约，expectedVersion／稳定 requestId 保存并读回 database／stored。不得重开或覆盖已完成的交付 run，不抢原会话租约。写入冲突重读合并，响应不明先按原 ID 核对；合法接口或锁暂不可写时保存待同步及准确原因，后续原每日轮次补齐。
- 原任务关联可读观察产物，至少记录观察键、基线、检查时刻、来源真实日期／窗口／维度、三类指标及对比、缺口、结论、下一阶段和补齐条件。daily 日期只用于存证目录及本轮执行，不构造新的问题身份。
- 同一阶段及相同来源版本已完整保存则复用；来源更新或缺口补齐时仅追加差分，不覆盖旧观测。缺一类资料不阻止其他类保存；阶段保留部分完成／待补，缺口清单每天继续检查，不能跨到第 14 天后遗忘第 7 天缺口。
- 每日原回执分列扫描覆盖、到期、完成、部分待补、复用、无到期及写入失败数量，附真实 taskId／链接和下次条件。周报与旧页轮查读取该回执；配置已更新、检查已启动、数据已保存和完整阶段完成分别描述，不把交付量或结单率当增长。
